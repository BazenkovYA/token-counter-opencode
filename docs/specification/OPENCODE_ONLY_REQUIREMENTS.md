# Требования к Token Counter для OpenCode

## Назначение

Приложение работает как локальный OpenAI-compatible proxy между OpenCode и уже
существующим LiteLLM gateway. Оно учитывает числовой usage каждого вызова,
сопоставляет событие с OpenCode Session ID и показывает состояние контекста.

Поддерживается один рабочий профиль: `opencode_litellm`. Приложение не управляет
моделями, inference runtime или gateway и не выполняет генерации при установке.

## Переносимость

- Репозиторий можно клонировать в любую локальную папку.
- Все внутренние пути вычисляются от корня проекта.
- `.venv`, runtime, SQLite, логи, exports, backup и секреты исключены из Git.
- Поддерживаются `scripts/install.ps1` и `scripts/install.sh` с Python 3.12+.
- Подключение OpenCode выполняется только явным флагом установщика и имеет rollback.

## Маршрут и ключи

- Сервис слушает только `127.0.0.1:8001`.
- Панель и `/api/*` открываются локально без формы входа.
- `/v1/*` требует отдельный client key, `/internal/*` — admin key.
- Upstream key берётся по ссылке на существующую переменную окружения.
- Значения ключей нельзя выводить, сохранять в Git или встраивать в OpenCode JSON.
- Redirect запрещён, TLS проверяется, proxy variables окружения не наследуются.

## Подключение OpenCode

Коннектор меняет только `baseURL` и `apiKey` выбранного provider и устанавливает
плагин из `integrations/opencode/token-counter.js`. До применения проверяются
исходный SHA-256, provider ID, aliases, лимиты, локальный сервис и конфликт другой
копии. Перед записью создаётся backup. Модели, MCP и остальные настройки сохраняются.
При переходе с проверенной предыдущей копии повторно используется её client key;
старый plan/env/plugin сверяются до чтения и переноса значения. Это сохраняет
работоспособность уже открытого процесса OpenCode.

Плагин добавляет Session ID, instance ID, message ID, parent/project ID, agent и
тип запроса. Он работает только для ожидаемого provider и точного loopback URL.

## Учёт

- Один HTTP-вызов `/v1/chat/completions` создаёт одно итоговое событие.
- JSON и SSE передаются без изменения содержимого модели.
- `stream_options.include_usage=true` добавляется с сохранением прочих параметров.
- Upstream POST никогда автоматически не повторяется.
- Ноль отличается от неизвестного значения; отсутствующий usage не оценивается.
- Cache/reasoning details не прибавляются повторно к prompt/completion.
- Источник и статус лимита сохраняются вместе с событием.
- Fallback к другой модели делает лимит события неизвестным.
- Текущий контекст выбирается по порядку начала main-вызовов; старое позднее
  завершение не заменяет более новый вызов.

Формулы: занято `P+C`, остаток `max(0,L-P-C)`, заполнение
`100*(P+C)/L`. Это оценка последнего учтённого вызова, а не состояние KV-cache.

## Хранение и приватность

SQLite работает в WAL. В базе сохраняются числовой usage, модель, времена,
статусы и служебные ID. Тексты сообщений, ответы, reasoning, tool results,
вложения, cookies и ключи не сохраняются. Названия сессий читаются из OpenCode
SQLite отдельным read-only адаптером с TTL; сообщения не читаются.

Очередь записи ограничена. Ошибка SQLite не должна повреждать HTTP-ответ; health
показывает write failures и потерянные события. Экспорт создаётся из одного
SQLite snapshot и включает CSV, JSONL, metadata, manifest и ZIP.

## Интерфейс и API

Панель на русском обновляется автоматически и показывает состояние сервисов,
модели, сессии, текущий вызов, заполнение, накопленные суммы и историю. Неизвестные
числа отображаются как `—`. Все UI assets локальные, CSP включён, CDN отсутствует.

Поддерживаемые API перечислены в `docs/api.md`. Неизвестные OpenAI endpoints
возвращают 501. История использует стабильный snapshot cursor.

## Приёмка

1. Чистый clone устанавливается из произвольного пути, включая путь с пробелами.
2. OpenCode connection изменяет только разрешённые поля и создаёт rollback backup.
3. Панель открывается по loopback без ввода пароля.
4. `/v1` без client key возвращает 401, `/internal` без admin key — 403.
5. JSON/SSE, ошибки, отмена, usage и Session ID проходят интеграционные тесты.
6. В SQLite и логах отсутствуют тексты запросов, ответов и секреты.
7. Doctor, Python tests и Node plugin tests завершаются успешно.
8. После ручного запроса пользователя событие появляется в панели без потерь.
