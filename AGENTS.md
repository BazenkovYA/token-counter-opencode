# Инструкции агенту по этому репозиторию

Корень проекта определяется по расположению этого файла. Не предполагай имя диска,
каталога или пользователя. Все внутренние пути строй от корня; внешние пути OpenCode
и metadata определяй через домашний каталог пользователя или явные параметры.

Перед изменениями прочитай `README.md`, `INSTALL_WITH_AI.md` и
`docs/connection.md`. Не читай и не печатай значения `.env`, `client.key`, рабочих
backup или переменных с API keys. Для диагностики выводи только наличие, длину,
булевы сравнения и HTTP-статусы. Не добавляй runtime, БД, логи, exports, `.venv`,
пользовательские конфиги или секреты в Git.

Поддерживаемые способы установки — `scripts/install.ps1` и `scripts/install.sh`.
Не заменяй их вручную наборами команд, пока не выяснишь причину их отказа. Для
OpenCode подключение разрешается только явным `-ConnectOpenCode` /
`--connect-opencode`; оно должно сохранить backup и оставить модели/MCP без изменений.
Не редактируй Desktop/app.asar, gateway или чужие процессы.

До коммита запусти Python-тесты и Node-тест плагина. При изменении установщика
проверь корень с пробелами и отсутствие абсолютных внутренних путей в созданном env.
Реальные генерации не входят в установочную проверку. GET `/models`, mock upstream
и синтетические данные допустимы. После подключения попроси пользователя полностью
перезапустить OpenCode и самому отправить один новый короткий запрос.

Не выполняй `git push`, не создавай удалённый репозиторий и не публикуй проект без
явного запроса. Локальные коммиты допустимы. Не переписывай историю Git после того,
как пользователь начал использовать внешний remote.
